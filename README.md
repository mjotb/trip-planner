# مخطط الرحلة

تطبيق عربي (RTL) لتخطيط الرحلات متعددة المدن. مبدؤه الوحيد:

> **تلوين يوم بلون مدينة = «سأبيت ليلةَ هذا اليوم في تلك المدينة».**

من هذه القاعدة يُشتق جدول حجوزات جاهز (دخول / خروج / عدد ليالٍ) بلا حجز مزدوج في يوم الانتقال، وبلا ليلة زائدة في يوم المغادرة.

يعمل بالكامل في المتصفح: لا سيرفر، لا حساب، لا اشتراك. يُثبَّت على شاشة الجوال كتطبيق (PWA).

---

## المشكلة التي يحلّها

مخططات الرحلات تُكتب عادة «لندن 22–24، أمستردام 24–28»، وهي صيغة غامضة تسبب أخطاء متكررة:

| المشكلة | الخطأ الشائع | الحل هنا |
|---|---|---|
| يوم الانتقال مشترك بين مدينتين | حجز ليلة في المدينتين لنفس التاريخ | اليوم يُعرض بلونين، ويُحسب ليلة واحدة للمدينة الجديدة فقط |
| يوم المغادرة النهائي | حجز ليلة لا يبيتها المسافر | يظهر بإطار متقطع «خروج» ولا يُحسب ليلة |
| عدّ الأيام بدل الليالي | اختلاف بين أيام الرحلة وليالي الفنادق | وحدة الحساب هي الليلة حصريًا |
| ربط التواريخ بالتقويم الهجري | حساب يدوي منفصل | كل يوم يعرض مقابله الهجري (أم القرى) |

## الشاشات

| # | الشاشة | ماذا تفعل |
|---|---|---|
| ١ | **رحلتي** | نظرة كاملة: الإحصاءات، تذاكر الطيران، المدن والفنادق مع روابط الخرائط، وزر نسخ جدول الحجوزات |
| ٢ | **الليالي** | التقويم المزدوج (ميلادي + هجري). اختر مدينة ثم لوّن أيام المبيت — تُشتق كتل الحجز فورًا أسفل الشاشة |
| ٣ | **اليوم** | مسار ساعة بساعة لكل يوم: مواصلات، مطاعم، معالم، وسطر انتقال بين كل عنصرين |
| ٤ | **أماكني** | مطاعم وأماكن محفوظة، تُضاف لأي يوم بنقرة، مع حفظ المنيو المترجم |
| ٥ | **رحلاتي** | إدارة رحلات متعددة، والنسخ الاحتياطي (تصدير/استيراد JSON) |

## التشغيل محليًا

```bash
npm install
npm run dev        # http://localhost:3000
```

اختبارات:

```bash
npm test           # منطق الليالي واشتقاق الحجوزات (17 اختبارًا)
npm run test:store # فحص دخان لأفعال المتجر (22 فحصًا)
npm run test:all
```

بناء نسخة ثابتة:

```bash
npm run build      # المخرجات في out/
npm start          # معاينة النسخة المبنية
```

## النشر على GitHub Pages

الملف `.github/workflows/deploy.yml` جاهز. الخطوات مرة واحدة فقط:

1. ارفع المشروع إلى مستودع على GitHub (فرع `main`).
2. من صفحة المستودع: **Settings → Pages → Source → GitHub Actions**.
3. ادفع أي تغيير — يبني الـ workflow المشروع تلقائيًا وينشره.

الرابط سيكون: `https://<اسم-المستخدم>.github.io/<اسم-المستودع>/`

الـ workflow يمرّر اسم المستودع في `NEXT_PUBLIC_BASE_PATH` تلقائيًا، فتعمل الأصول تحت المجلد الفرعي بلا تعديل يدوي.

> بديل أسرع: اربط المستودع بـ [Vercel](https://vercel.com) — يبني وينشر بلا إعداد، وعلى نطاق أنظف.

## التثبيت على الجوال

افتح الرابط في متصفح الجوال ثم:

- **iPhone (Safari)**: زر المشاركة ← «إضافة إلى الشاشة الرئيسية»
- **Android (Chrome)**: القائمة ← «تثبيت التطبيق»

يفتح بعدها بملء الشاشة بلا شريط متصفح، ويعمل بلا إنترنت بعد أول فتح (عدا خط Poppins).

## البيانات والنسخ الاحتياطي

كل شيء محفوظ في `localStorage` داخل متصفحك — لا يغادر جهازك.

هذا يعني أن مسح بيانات المتصفح يمسح رحلاتك. لذلك:

1. من تبويب **رحلاتي** ← «تنزيل نسخة احتياطية (JSON)».
2. ضع الملف في Google Drive أو OneDrive.
3. على أي جهاز آخر: «استيراد وإضافة» (يدمج مع الموجود) أو «استيراد واستبدال» (يستبدل كل شيء).

## الذكاء الاصطناعي — جسر النسخ واللصق

لا يحتاج التطبيق مفتاح API ولا يكلّف شيئًا. يستفيد من اشتراكك الحالي في Claude أو ChatGPT:

**اقتراح مسار يوم** (تبويب رحلتي أو اليوم ← «تحسين المسار»):

1. التطبيق يبني الطلب كاملًا — المدينة، الفندق، التاريخ، ما هو مجدول أصلًا، اهتماماتك.
2. اضغط «نسخ الطلب»، الصقه في تطبيق Claude.
3. انسخ الرد كاملًا والصقه في الحقل الثاني ← «أضف الناتج إلى الخطة».

**ترجمة منيو** (أماكني ← «ترجمة المنيو»): نفس الخطوات، لكن أرفق **صورة المنيو** مع الطلب في Claude. الناتج يُحفظ مع المكان.

لا يهم إن أضاف النموذج شرحًا حول الـ JSON — المُحلِّل يستخرج الجزء المطلوب، ويصحّح الأوقات الناقصة والأنواع غير المعروفة.

**لو أردت لاحقًا ربطًا تلقائيًا بمفتاح API**: أضف مسار API واستبدل زر النسخ بنداء مباشر في `src/sheets/AiSheet.tsx`. الطلبات والمُحلِّلات جاهزة في `src/lib/ai.ts` — لن تحتاج تغييرها.

## ما تغيّر عن النموذج الأولي

النموذج المرجعي (`design_handoff_tourly_planner`) كان مثبّتًا على أكتوبر ونوفمبر 2026. أهم ما عولج هنا:

- **التواريخ حرة**: مفاتيح الأيام صارت ISO (`YYYY-MM-DD`)، فأي مدى يعمل — بما فيه عبور نهاية السنة والسنوات الكبيسة.
- **التقويم الهجري حقيقي**: `Intl.DateTimeFormat('ar-SA-u-ca-islamic-umalqura')` بدل إزاحات ثابتة كانت صحيحة لخريف 2026 فقط.
- **رحلات متعددة** بدل رحلة واحدة، مع حفظ دائم ونسخ احتياطي.
- **عدّاد الليالي أُصلح**: كان لا يعمل إطلاقًا لمدينة بلا ليالٍ سابقة.
- **الأيقونات الناقصة** (طائرة، قطار، سرير، تقويم، ساعة، سيارة) أُنشئت بنفس أسلوب التصدير.
